# D'Agostino Legal — Financial Operations Dashboard

A Streamlit dashboard that behaves like a working Financial Analyst's tool for a small law firm:
reporting periods (MTD / QTD / FY / custom) with prior-period or year-on-year comparison, P&L versus budget,
FY outlook, 13-week cash forecast, receivables and WIP, trust account, and a dedicated evaluation dashboard for each
of seven practice-management platforms.

> **All data is synthetic.** It is generated by a deterministic model (`core/model.py`) and calibrated so the firm's
> headline balances on the as-of date (17 Sep 2025) are exact: 142 active matters, office cash $268,400, trust $535,000.
> Platform prices, scores and productivity uplifts (`core/platforms.py`) are illustrative assumptions, **not vendor facts**.
> Replace them with real quotes and demo findings before using them for a decision.

## Run

```bash
pip install -r requirements.txt
streamlit run app.py
```

Python 3.10+; Streamlit 1.50 or newer. Optional: `pip install watchdog` so Streamlit reloads when you edit a file.

## Using it

* **Top bar** — page navigation and the **reporting period** picker (📅). Every page follows it. Choose a comparison
  (prior period / same period last year / none). Custom ranges are supported. Data starts 1 Jul 2023, so comparisons
  that would fall before that show "n/a".
* **Sidebar** — click a wedge of the polar chart or a platform button to open that platform's own dashboard
  (Summary, Cost & TCO, Cash flow & NPV, Scorecard, Implementation & risk, Sensitivity). Scenario, discount rate and
  criteria weights are adjustable; every platform is measured against the current system (LEAP + InfoTrack).
* **Pages** — Overview · Matters · Clients · Calendar · Finance (P&L vs budget, FY outlook, Cash, Billing & WIP,
  Trust account, Suppliers & costs) · Team · Simulator (what-if levers with saved scenarios).

## How the numbers hang together

```
hours × rates → value → WIP roll-forward → fees billed → invoice ledger → collections → office cash
fees + disbursements → revenue → P&L (actual vs budget) → GST / BAS / partner drawings → bank balance
```

Monthly figures are stored as full-month equivalents; a period query weights each month by the days it overlaps, so
MTD, QTD, financial years and custom ranges all reconcile exactly (see `core/period.py`).

| Path | What it holds |
|---|---|
| `app.py` | Entry point: sidebar, top bar, period control, page router |

| `views/` | One module per page (`platform_view.py` serves all seven platforms) |
| `tests/test_reconciliation.py` | 18 tests proving pages agree with each other |

## Common changes

* **Change the as-of date, seed, opening balances or cash target** → `core/ref.py` (`AS_OF`, `OFFICE_CASH_AT_AS_OF`) and `SEED` in `core/model.py`.
* **Add a client / attorney / branch** → the lists in `core/ref.py`; the model regenerates everything from them.
* **Update platform prices or scores** → `PLATFORMS` in `core/platforms.py`.
* **Overview height** → `SCREEN_H` in `views/overview.py` (768 / 820 / 890 / 1080). All cards and the globe scale from it.
* **Use real data** → replace what `build_model()` returns with your own frames of the same shape (see the docstring at the top of `core/model.py`).

## Known limitations

* The globe needs internet access (Plotly loads world geometry from its CDN).
* Cash cover looks short by design: partners draw most of each month's profit; WIP and receivables are the buffer.
* Fixed costs (payroll, rent, software, insurance) equal budget exactly, so their variance is $0.
* The Simulator is an annual what-if on the last 12 months and assumes enough work exists for any new hire.
* The matter ledger and the intake funnel are modelled, not imported from a practice-management system.
