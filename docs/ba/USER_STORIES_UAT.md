# User stories and UAT

Each story is accepted by a UAT check run on the sample data (17 Sep 2025) and by an automated test, so it is re-checked on every change.

| ID | User story | Acceptance criteria | UAT result | Automated test |
|---|---|---|---|---|
| US1 | As the Principal, I want to compare software platforms on cost and return, so that I switch only if it pays | 7 platforms ranked by score and NPV; current system is the baseline | Pass: Smokeball + GlobalX ranked 1, NPV +$106K | `test_reconciliation.py::test_platforms`, `test_simulator_engine.py::test_platform_switch_uses_the_platform_evaluation` |
| US2 | As the Principal, I want to see a new branch's payback and cash impact, so that I do not run out of cash | Year-one and full-speed result, payback month, fit-out as one-off cash | Pass: −$87K year one, payback 17 months, cash low point $40K | `test_simulator_engine.py::test_branch_fit_out_is_cash_not_profit_and_pays_back` |
| US3 | As a partner, I want to know which practice area to hire for, so that a new lawyer is busy from day one | Areas ranked by pressure, demand and margin; SQL gives the same ranking | Pass: Litigation first in the app and in SQL | `test_sql_queries.py::test_where_to_hire_matches_the_app` |
| US4 | As the Principal, I want a hire's profit to depend on the area, so that the recommendation is testable | Hiring in the top area earns more than in the weakest | Pass: Litigation +$130K vs Advisory +$82K | `test_simulator_engine.py::test_hire_in_the_top_area_beats_the_weakest` |
| US5 | As the Practice Manager, I want support headcount compared with workload by office, so that I can rebalance teams | Status per office and department; SQL gives the same roles needed | Pass: Camden reception over-staffed (+1.8) | `test_sql_queries.py::test_support_staffing_matches_the_app` |
| US6 | As the Practice Manager, I want the cost of cutting roles to include NES redundancy and notice, so that the saving is real | Redundancy weeks by service, notice weeks, small-business exemption | Pass: 2 roles, 3 years: 7 weeks redundancy, 2 weeks notice each | `test_simulator_engine.py::test_nes_redundancy_table_and_small_business_exemption`, `::test_department_cut_uses_that_department_pay` |
| US7 | As the Principal, I want to know what a pay rise costs and how to fund it, so that the pay review is affordable | Cost a year; rate rise that restores profit; warning below market wage growth | Pass: 3% costs $119K; rates +1.7% fund it | `test_simulator_engine.py::test_pay_rise_costs_payroll_and_rate_to_fund_it_restores_profit` |
| US8 | As the marketing coordinator, I want cost per new matter by channel, so that budget goes where it works | Spend, inquiries, new matters and cost per matter by channel; SQL agrees | Pass: Website & SEO $646, LinkedIn $2,243 | `test_sql_queries.py::test_marketing_channels_match_the_app` |
| US9 | As the Principal, I want extra marketing to show diminishing returns, so that the model does not reward unlimited spend | More spend eventually earns less; a weak channel loses money | Pass: $10K a month earns less than $3K; LinkedIn loses money | `test_simulator_engine.py::test_marketing_has_diminishing_returns_and_channels_differ` |
| US10 | As the Principal, I want to test a new matter type, so that I know the launch cost and payback | Launch as one-off cash, ramp-up, payback, delivery risk | Pass: Wills & Estates, $25K launch, payback 13 months | `test_simulator_engine.py::test_new_matter_type_launch_is_one_off_cash_and_ramp_matters` |
| US11 | As the Financial Analyst, I want the answers in Excel, refreshable by Power Query, so that finance can use them without Python | Data sheets as Excel tables; summary is formulas only; Power Query reads files that exist | Pass: summary recalculates to $471K profit vs $507K budget | `test_excel_and_exports.py` |
| US12 | As the Financial Analyst, I want the same tables and decision queries in Snowflake, so that the analysis runs in the warehouse | Every table created and loaded; no SQLite-only functions in the Snowflake SQL | Pass (generated scripts checked; run in Snowflake to confirm) | `test_docs.py::test_snowflake_setup_creates_every_warehouse_table`, `::test_snowflake_queries_use_no_sqlite_functions` |
| US13 | As the Principal, I want the whole analysis in Power BI, so that I can read it in the tool the firm already uses | Every page builds from the model; every field and DAX reference exists; the Simulator's DAX matches the Python engine | Pass: 21 pages, schema-valid; formula spec matches the engine for every preset and 300 random mixes | `test_powerbi.py` and the report's Check page |
